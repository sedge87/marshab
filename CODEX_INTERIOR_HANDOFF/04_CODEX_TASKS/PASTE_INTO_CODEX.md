# Codex task: replace greybox Mars Habitat interiors with grounded Blender assets — safety first

Read this handoff folder AND the current Godot repository before making changes. In particular read `docs/interior-asset-brief.md`, `docs/equipment_handoff.md`, `data/equipment_catalog.json`, `scripts/build_controller.gd`, `scripts/equipment_catalog.gd`, `data/parts_catalog.json`, related tests and any local AGENTS.md. The grey-box meshes are **prototypes only**. The goal is a coherent library of grounded, plausible Mars research-station interiors, NOT neon futuristic décor.

**Execution instructions**
1. Audit where every placeholder comes from: imported GLB, generated meshes in GDScript, and any Godot scenes. Identify the asset IDs and the exact paths/references, source Blender scripts, collision and save dependencies. Output an audit table.
2. BEFORE any replacement, run `python CODEX_INTERIOR_HANDOFF/05_SAFETY_TOOLS/snapshot_existing_art.py --project .` or make an equivalent timestamped copy to `backups/interior_greybox_YYYYMMDD_HHMMSS/`; include live catalogue, generated-art scripts, implicated `.gd`/`.tscn`, original GLBs/materials and asset manifest. The script is snapshot-only; examine its report. Make a dedicated Git commit/branch too where supported. NEVER delete backups, rely solely on Git, or overwrite original .blend files.
3. Build a reusable Blender 4.x (or actual installed supported version) model generator and editable .blend sources. Use procedural modelling for repeatability; don't just render or create boxes with arbitrary colours. Strong readable silhouettes, bevels, inset panels, hinge details, handles, filtered grilles, ducts/hoses, vents, labelled interfaces and restrained indication lights.
4. First make a visual material/style kit plus interior wall, sliding door and observation window **without** bypassing structural or pressure rules. Then build a showcase `grow_tray` in its valid zone. Integrate the new visual using its catalogue `asset_scene`; preserve resource/placement IDs and all effects.
5. Expand batch to `crew_bunk`, `air_recycler`, `science_workbench`, `cargo_rack`. Where model filenames differ from IDs (e.g. `locker` uses personal_locker.glb), respect existing `asset_scene` rather than guessing paths. Follow the production order and inventory CSV. Continue catalogue-wide only after the vertical-slice quality is established and tests pass.
6. Replace presentation-only greybox code paths with model loading and an explicit safe placeholder fallback only when the external asset cannot load. Never leave greybox covering the new mesh. Preserve snapping, collision, room restriction feedback, resource counts, removal, player navigation and save/load. Maintain active/off/warning states where they are currently implemented; only add new interaction logic with proper integration tests.
7. Build **actual models** (Blender source `.blend` and `.glb`) and integrate into Godot. A script that would generate models, but has not been run, is NOT sufficient: run Blender if available and inspect exported results. If Blender is unavailable in the execution environment, create and verify runnable Blender scripts but clearly label models unbuilt and do not claim integration complete.
8. Run Godot headless import/project/test checks if available; test placement, resource readiness, power failure state, click/E interaction, removal, save/load, alignment, collision, frame-rate and fallback. Include one in-game screenshot per prototype and report any unverified manual steps. Do not mark an unverified behaviour tested.
9. Create `docs/interior-replacement-progress.md` with completed IDs, backups, modified paths, screenshots, tests, open issues and next assets. Do not modify the source copy inside this handoff folder.

**Design priority**: NASA CHAPEA, HERA, ISS engineering racks, Antarctic labs and practical hydroponic stations > The Martian > Starfield/Subnautica/No Man's Sky. No glow-heavy sci-fi furniture, no generic grey cubes. Small touches of warm comfort are fine. See `01_ART_DIRECTION/GROUNDED_STYLE_GUIDE.md` and `02_REFERENCES/OPEN_MOODBOARD.html`.

**Scope safety**: This is an interior asset overhaul, not an engine rewrite. Do NOT change external pressure hull/airlock physics, structural connectors, resource balance, crew assumptions or existing saves without direct necessity and regression tests. Do not use game reference images as textures or rip proprietary assets. If the supplied handoff snapshot conflicts with current repository, **current code wins**, and log the difference.

**Reporting**: brief initial audit and implementation plan, then execute the full safe first batch. At the end provide a concrete list of `.blend`, `.glb`, scene/script changes, snapshot location, tests pass/fail, runtime screenshots and follow-up priorities.
